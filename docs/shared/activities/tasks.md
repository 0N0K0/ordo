# Paquet partagé : `tasks`

Schémas et fonctions des tâches, contributeurs, jalons, sprints, colonnes du tableau des tâches, temps passé, alarmes et lien GitHub. Source : `packages/shared/src/tasks/`.

Voir aussi : [Règles : tâches](../../business-rules/activities/tasks.md), [Règles : temps](../../business-rules/activities/time.md), [Règles : alarmes](../../business-rules/activities/alarms.md), [Personnes](../../business-rules/cross-cutting/people.md), [Dates](../../business-rules/cross-cutting/dates.md).

## `tasks.ts` — tâches, contributeurs, jalons, sprints

| Export                                            | Rôle                                                                                                                                                                                            |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `taskLabelSchema`                                 | Libellé de tâche : `requiredText()` (requis, 250 caractères max, décision DO).                                                                                                                  |
| `effortSchema`                                    | Effort : nombre (« Nombre attendu. »), ≥ 0 (« L’effort ne peut pas être négatif. »), ≤ 1 000 000 (« Valeur trop grande. »), facultatif.                                                         |
| `effortFieldSchema`, `effortFormSchema`            | Effort tel qu’un champ nombre le tient (`''` devient `null`, puis `effortSchema`), seul (`{ effort }`) : l’effort du panneau d’une tâche, enregistré en le quittant (décision D22). |
| `commentBodySchema`                               | Commentaire : `markdownTextSchema` (65 536 max) non vide (« Le commentaire est vide. »). Les textes markdown suivent `markdownSchema` de [core](../cross-cutting/core.md) (`core/rules.ts`).    |
| `HANDLE_MAX`                                      | `39` (comme les identifiants GitHub).                                                                                                                                                           |
| `handleSchema`                                    | Identifiant de mention `@` : `trim`, minuscules, 2 à 39 caractères, lettres, chiffres, « - » et « _ », ni « - » ni « _ » au début ou à la fin.                                                  |
| `suggestHandle(name)`                             | Propose un identifiant depuis un nom (« Noémie Koelblen » → « noemie-koelblen »).                                                                                                               |
| `contributorFormSchema` / `ContributorFormValues` | Contributeur : `name` (nom de personne), `handle`, et ses détails (`personDetailsShape` : date de naissance, rappels d'anniversaire, adresses mail (lot 16c), téléphones, lot 16).                                                                                                                                              |
| `taskFormSchema` / `TaskFormValues`               | Formulaire de tâche (tableau ci-dessous). Règles : fin après début (`startDate` / `endDate`) et échéance après l’ouverture (`minDate` / `deadline`).                                               |
| `milestoneLabelSchema`                            | Libellé de jalon : requis, 250 max.                                                                                                                                                             |
| `milestoneFormSchema` / `MilestoneFormValues`     | Jalon : `label`, `dueDate` (facultatif), `description`.                                                                                                                                         |
| `sprintLabelSchema`                               | Libellé de sprint : requis, 250 max.                                                                                                                                                            |
| `sprintSchema(goal)`                              | Sprint : `label`, `startDate` (« La date de début est requise. »), `endDate` (« La date de fin est requise. »), fin après début, `goal` (texte simple dans le formulaire, markdown pour l'API). |
| `sprintFormSchema` / `SprintFormValues`           | `sprintSchema(z.string())`.                                                                                                                                                                     |
| `taskDueDates(task, sprintOf)` / `TaskOwnDates`, `SprintDays`, `TaskDueDates` | « Ouverture » / « Échéance » qu'une tâche suit : les siennes ; sans l'une ou l'autre, celle de son sprint quand elle est dans exactement un sprint (début, fin) ; plusieurs sprints : rien d'hérité ; avec `minDateFromSprint`, `deadlineFromSprint`. Seul calcul de l'héritage, utilisé par l'API (champs `effectiveMinDate`, `effectiveDeadline`…). |
| `TaskInput`                                       | Champs envoyés pour créer ou modifier une tâche : `undefined` laisse inchangé, `null` efface (le lieu avec son point, les liens : `null` n'en laisse aucun).                                                                                                   |

Champs de `taskFormSchema` :

| Champ                                         | Règle                                                                                                         |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `label`                                       | Requis, 250 max.                                                                                              |
| `projectId`                                   | Vide : tâche sans projet (`null`).                                                                            |
| `description`                                 | Texte.                                                                                                        |
| `statusId`, `priorityId`, `typeId`            | Facultatifs.                                                                                                  |
| `assigneeIds`, `tagIds`, `sprintIds`          | Listes d'ids.                                                                                                 |
| `effort`                                      | `effortFieldSchema` : `''` devient `null`, puis `effortSchema`.                                               |
| `startDate`, `endDate`, `deadline`, `minDate` | Jours facultatifs ; « Ouverture » : pas avant ce jour.                                                         |
| `parentId`, `milestoneId`                     | Facultatifs.                                                                                                  |
| `beneficiaryIds`, `beneficiaryRelationIds`    | « Bénéficiaires » : contributeurs et relations pour qui est la tâche.                                         |
| `slotCondition`                               | Condition de créneaux, celle des routines (voir [calendar](calendar.md)) ; `null` : n'importe quand.            |
| `location`                                    | Lieu (décision D6) : texte, 250 max, vide devient `null` ; avec `locationPointFields` (son point, sans trajet). |
| `links`                                       | Liens (décision D5) : `itemLinksSchema` (voir [core](../cross-cutting/core.md)), `[]` par défaut.               |
| `reminders`                                   | Rappels (décision D16) : `taskRemindersSchema` (voir [dates](../cross-cutting/dates.md)), « À HH:MM » seulement, `[]` par défaut. |
| `deadTimes`                                   | Temps morts (décision FT) : `deadTimesSchema` (voir [dates](../cross-cutting/dates.md#countdownsts--minuteurs-et-temps-morts-décision-ft)), `[]` par défaut ; `TaskInput.deadTimes` : `null` = aucun, omis = inchangé. |

- `taskRef(task)` (« #12 », vide sans projet) et `taskNumbered(task)` (« #12 Libellé ») : déplacés du web (lot 17c, aussi pour les sonneries poussées) ; le web les réexporte (`use-task-context`).

## `task-columns.ts` — colonnes, statuts, regroupements

| Export                                            | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TASK_STATUS_CATEGORIES` / `TaskStatusCategory`   | Sens fixe d'un statut : `TODO`, `IN_PROGRESS`, `DONE`, `CANCELLED`.                                                                                                                                                                                                                                                                                                                                                  |
| `statusClosing(from, to)`                         | Effet d'un changement de statut sur l'état fermé (décision D23) : vers « Annulé » `'close'`, hors de « Annulé » `'reopen'`, sinon `null` (« Terminé » compris). Utilisé par `closeOnStatus` (API). |
| `TASK_STATUS_CATEGORY_LABELS`                     | Noms accordés : `status` (« À faire », « En cours », « Terminé », « Annulé ») et `task` (« Terminée », « Annulée »).                                                                                                                                                                                                                                                                                                 |
| `TASK_COLUMNS` / `TaskColumn`                     | Colonnes du tableau des tâches : `label`, `project`, `status`, `priority`, `type`, `assignees`, `beneficiaries`, `tags`, `effort`, `trackedTime`, `startDate`, `endDate`, `deadline`, `minDate`, `slots`, `location`, `timer`, `parent`, `subtasks`, `progress`, `milestone`, `sprint`, `blockedBy`, `blocking`, `related`, `comments`, `alarms`, `shopping`, `createdAt`, `updatedAt` (le numéro est affiché avant le libellé). |
| `EVENT_PERIODS` / `EventPeriod`                   | Périodes des événements listés avec les tâches : `thisWeek`, `nextWeek`, `thisMonth`, `nextMonth`, `next:7`, `next:30`, `next:90`, `past:30`.                                                                                                                                                                                                                                                                        |
| `TASK_GROUP_BY` / `TaskGroupBy`                   | Regroupements possibles : `state`, `project`, `status`, `priority`, `type`, `assignees`, `beneficiaries`, `tags`, `parent`, `milestone`, `sprint`, `blockedBy`, `blocking`, `related`, et par mois `startDate`, `endDate`, `minDate`, `deadline`.                                                                                                                                                                    |
| `DEFAULT_HIDDEN_COLUMNS`                          | Masquées par défaut : `location`, `blocking`, `related`, `milestone`, `createdAt`, `updatedAt`.                                                                                                                                                                                                                                                                                                                                  |
| `taskColumnDefaultsSchema` / `TaskColumnDefaults` | Colonnes de départ des nouvelles vues de tâches d'un espace : `columnOrder`, `hiddenColumns` (200 ids max ; `label` ne peut jamais être masqué).                                                                                                                                                                                                                                                                     |
| `readTaskColumnDefaults(stored)`                  | Valeur stockée de l'espace (ancien id `title` lu comme `label`), sinon mise en page vide (celle de l'application).                                                                                                                                                                                                                                                                                                   |

## `time.ts` — temps passé et alarmes

| Export                                                   | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `timeDescriptionSchema`                                  | Ce qui a été fait : `markdownSchema` (markdown, 65 536 max, « Texte trop long. »), blanc devient `null`.                                                                                                                                                                                                                                                                                                                                                                                   |
| `durationSchema`                                         | Durée en secondes : entier, 60 à 86 400 (« Au moins 1 minute. », « 24 heures maximum. »).                                                                                                                                                                                                                                                                                                                                                                                                  |
| `timeEntryFormSchema` / `TimeEntryFormValues`            | Saisie manuelle : `projectId`, `routineIds`, `taskIds`, `events` (clés d’occurrence des évènements), plusieurs de chaque (décision D18), `description`, `date` (« La date est requise. »), `start` (`HH:MM`), `duration` (`durationTextSchema`). Au moins un projet, une tâche, une routine ou un évènement (`TIME_SUBJECT_REQUIRED` : « Choisissez un projet, une tâche, une routine ou un évènement. », sous `projectId`, décision D17).                                                                                                                                                                   |
| `parseDuration(text)`                                    | Lit « 1:30 », « 1h30 », « 1 h », « 45 min », « 90 » (minutes), « 1,5h » (heures) ; secondes, ou `null` si invalide ou hors 1 min – 24 h.                                                                                                                                                                                                                                                                                                                                                   |
| `DURATION_TEXT_INVALID`, `durationTextSchema`              | Une durée tapée dans un champ (`parseDuration`) : « Durée attendue : 1:30, 1h30, 90 (minutes) ou 1,5 h. » ; le formulaire et la cellule d’un temps, le minuteur, les temps morts. |
| `durationText(minutes)`                                  | Une durée comme on la tape (« 1:30 », « 0:05 ») : la valeur de départ d’un champ de durée. |
| `formatDuration(seconds)`                                | « 2 h 05 », « 45 min ».                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `formatClock(seconds)`                                   | Chronomètre « 1:05:09 ».                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `entrySeconds(entry, now?)`                              | Durée effective d'une saisie, pauses exclues : durée stockée une fois arrêtée, sinon calculée en direct jusqu'à la pause en cours, la fin ou maintenant.                                                                                                                                                                                                                                                                                                                                   |
| `ALARM_TYPES` / `AlarmType`                              | `REMINDER` (rappel), `NOT_TRACKING` (aucun suivi de temps en cours), `TRACKING_DURATION` (suivi en cours depuis une durée).                                                                                                                                                                                                                                                                                                                                                                |
| `ALARM_FREQUENCIES` / `AlarmFrequency`                   | Ancien format : `ONCE`, `DAILY`, `WEEKLY`, `MONTHLY`.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `alarmInputSchema` / `AlarmInput`                        | Alarme : `label` (requis, 250), `note` (texte multiligne, `optionalPlainText`, 4 000), `type`, `startDate`, `time`, `frequency`, `interval` (1 à 365), `weekdays`, `endDate`, `recurrence` (forme commune ; absente : anciens champs), `minutes` (1 à 1440), `projectId`, `taskId`, `enabled`. `TRACKING_DURATION` exige `minutes` (« La durée est requise. ») ; les autres exigent `startDate` (« La date est requise. ») et `time` (« L’heure est requise. ») et une fin après le début. |
| `alarmRule(schedule)`                                    | Règle de sonnerie : `recurrence` si valide, sinon conversion des anciens champs ; `ONCE` : `null` (une seule fois).                                                                                                                                                                                                                                                                                                                                                                        |
| `previousOccurrence(schedule, moment, lookBackDays = 2, timeZone?)` | Dernière sonnerie à ou avant un moment, en remontant au plus quelques jours (heure locale ; avec un fuseau, celui-ci : Paris pour le serveur qui sonne hors de l’app, lot 17c).                                                                                                                                                                                                                                                                                                                                                                                                |
| `nextOccurrence(schedule, moment)`                       | Prochaine sonnerie après un moment, sur environ deux ans (800 jours) ; `null` si terminée.                                                                                                                                                                                                                                                                                                                                                                                                 |

Internes : `AlarmSchedule`, `ringsOn` (sonne ce jour local), `at` (heure d'un jour local).

## `github.ts` — lien avec un tableau GitHub

| Export            | Rôle                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GithubLinkInput` | Réglages du lien d'un projet avec un tableau GitHub Projects : `url` ; ids des champs synchronisés (`statusFieldId`, `priorityFieldId`, `iterationFieldId`, `startFieldId`, `endFieldId`, `effortFieldId`, `deadlineFieldId`, `timeSpentFieldId`) ; `typeSource` (`FIELD`, `ISSUE_TYPE` de l'organisation, ou `null`) et `typeFieldId` ; correspondances `statusOptions`, `priorityOptions`, `typeOptions` (id Ordo → option GitHub) ; `syncAssignees`, `syncLabels` ; `repositoryName` (« owner/name », `null` pour des brouillons) ; `pushExisting` ; `enabled`. Un type (pas une interface) : les valeurs d'un formulaire. Voir [GitHub](../../business-rules/cross-cutting/github.md). |
| `REPOSITORY_FORMAT_ERROR` | « Forme attendue : compte/dépôt. » (sous le dépôt d'un lien ; aussi l'erreur de champ de l'API). |
| `githubLinkFormSchema` | Réglages d'un lien dans son formulaire : `repositoryName` vide ou « compte/dépôt » (`REPOSITORY_FORMAT_ERROR`) ; le reste se choisit dans le tableau. |
