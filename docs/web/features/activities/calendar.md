# Code web de l’agenda

Référence de chaque fichier de `apps/web/src/features/calendar/` (api, pages, components, hooks, lib) : composants, hooks, fonctions, constantes et types, leur rôle et où ils servent. Fonctionnalités : [Agenda](../../../features/activities/calendar.md) ; règles : [Règles de l’agenda](../../../business-rules/activities/calendar.md).

## api

### `api/index.ts`

Documents GraphQL (fragment `CalendarEventOccurrenceFields`, requêtes `WorkSchedules`, `ForeignScheduleKinds`, `SubscribedWorkSchedules`, `CalendarCategories`, `CalendarEvents`, `Calendars`, `SubscribableCalendars`, `SubscribedCalendarEvents`, mutations des calendriers, catégories, évènements, créneaux, types de créneaux, abonnements) et hooks TanStack Query. Toutes les mutations passent par `useCalendarMutation` (interne) : `useInvalidatingMutation` qui invalide `calendarQueryKey`, et les requêtes `also` données (`tasksQueryKey` pour `update` et `postpone` des évènements : un changement de projet y rattache les contributeurs).

## pages

### `pages/CalendarPage.tsx`

`CalendarPage()` : la page `/calendar` (route dans `app/router.tsx`). FullCalendar (`dayGrid`, `timeGrid`, `interaction`), réglé par `parisCalendarOptions` (`lib/paris-calendar.ts` : `luxon3` pour le fuseau nommé, locale `fr`, fuseau `Europe/Paris`) : ses dates (glisser, sélection, période affichée) sont lues à l’heure de Paris (`parisParts`), quel que soit le fuseau du navigateur.

- État : vues enregistrées (`useCalendarViews`, onglets `ViewTabs` avec `about` = `CALENDAR_VIEW_WORDS`) ; la configuration de la vue courante (`CalendarViewConfig`, `LOADING_VIEW` pendant le chargement) donne l’affichage (`display` → vue FullCalendar par `FULL_CALENDAR_VIEWS`), les éléments montrés (`tasks`, `routines`, `schedules`, `timers`, `includeArchived`, `hiddenCalendarIds`, `hiddenScheduleIds`), `fineSlots` et les filtres (`filters`) ; tout changement passe par `change(patch)` (copie de travail de la vue) ; dépliage de la ligne journée entière (`useState`, repliée à chaque ouverture, non mémorisé), période (`range`), titre, mode `editingSlots`.
- Filtres : `useCalendarFilters(config, …)` donne les sections de `CalendarFilters` (barre d’outils, après la navigation de période) et `kept` : un évènement de l’espace, une tâche, une routine, un temps, un créneau ou une éphéméride de l’espace non gardés ne sont pas ajoutés à `items` (les évènements abonnés et les créneaux d’autres espaces ne sont pas filtrés ; ni le mode `editingSlots`) ; l’export PDF part de `items`, il suit donc la vue et ses filtres.
- Paramètre `?date=` : `gotoDate` puis retiré (`useSetParams`).
- Effets : `materialize.mutate(range)` à chaque période ; `changeView` à chaque vue.
- `items` (mémo) : construit les `EventInput` FullCalendar, chacun avec `extendedProps.kind` : `event`, `travel`, `subscribed`, `time`, `editSlot` (créneau ou éphéméride du mode « Modifier les créneaux et éphémérides », en pointillés pour une éphéméride, aspect `slotLook(source, 'edit')`), `slot` (bandeau), `birthday` (anniversaire, évènement d’une journée entière non modifiable, `birthdayEvents` : un clic ouvre la personne, `usePersonOpener`), fonds de créneaux (sans kind, `display: 'background'`, `slotLane`, `slotColumn`/`slotColumns`), bandeaux et fines lignes, tous donnés par `slotEvents(shown, month)` (placés par `slotPlacements` selon l'affichage de leur type, dans leur aspect `slotLook`) ; un créneau archivé, ou d’un type archivé, dans son espace, seulement avec `includeArchived` ; en mode `editingSlots`, ceux de l’espace non archivés, d’un type archivé compris, sont des `editSlot`), `task` (`part` : `dates`, `open`, `deadline`), `routine`, `routineTravel`. Les bandeaux, fonds et fines lignes des créneaux, les `editSlot` et les anniversaires portent `extendedProps.print` (`SlotPrint` : nom du type pour la légende, couleur, motif `slotPattern`, clarté, archivé) : le PDF les dessine pareil. Utilise `occurrenceSpan`, `isArchivedOccurrence`, `scheduleSources`, `slotEvents`, `slotLook`, `taskPlacement` (`@ordo/shared`), `placeRoutineBlocks`, `manualOrder` (routines), `entryEventKeys`/`entrySubject` (temps : part hors de chacun de ses évènements, rien à côté d’un évènement d’une journée entière), `taggedKey`.
- `handleChange(info)` (interne) : glisser/étirer selon le kind (créneau ou éphéméride → `edits.changeSlot`, à heures sur un seul jour, message `slotWords(…).sameDay`, routine → `edits.changeRoutine`, tâche → `useUpdateTask`, évènement → `askScope` puis `update`, et, à heures pendant un créneau indisponible, `notifyWarning` « Évènement enregistré » avec `unavailableWarning(useSlotRules().unavailable(début, fin))`) ; `revert()` en cas d’annulation ou d’erreur.
- `select` : ouvre `useEventForm` pré-rempli ; `eventClick` : selon le kind (tâche → `useTaskLink`, temps → `useTimeEntryDialogs`, abonné → `SubscribedEvent` dans `openFormPanel`, créneau → `edits.openSlot`, routine → `edits.openRoutine`, sinon `EventForm`).
- Barre d’outils : interrupteur `StateSwitch` « Modifier les créneaux et éphémérides » (`editingSlots`) ; « Ajouter » (`ActionButton` à `menu`) : « Évènement » (`useEventForm`), `schedulesTitle(perso)` et `EPHEMERIDES_TITLE` (`openSchedulesManager`).
- `eventDidMount` : variables CSS `--slot-lane`, `--slot-column`, `--slot-columns`.
- Paramètres : `PageSettings` « Paramètres de l’agenda » avec `SettingsTabs` (`SETTINGS_TABS` = `display`, `settings`, `useSettingsTab`) : `CalendarDisplayChoices` (calendriers et créneaux : `calendarChoices`, `scheduleChoices`, les archivés seulement avec « Afficher les archivés » ; « Aussi dans l’agenda ») avec `ShowArchivedSwitch`, « Par 5 minutes », export PDF (`useAsyncAction` + `downloadCalendarPdf(pdfItems(items, { closed: classes.closed, archived: classes.archived }))`), « Semaines types » (`openFormPanel` « Semaines types » avec `TypicalWeeksPanel`, la période affichée et les créneaux masqués de la vue), `CalendarsIcsButton` ; `WeekSettings`, `CalendarsManager`, `CalendarCategoriesManager`, `ScheduleSettings`, puis en dernier `ScheduleColumnDefaults`.
- Constantes internes : `FULL_CALENDAR_VIEWS`, `DISPLAYS` (« Mois », « Semaine », « Jour », `SegmentedControl` « Affichage »), `LOADING_VIEW`, `NONE`, `CALENDAR_VIEW_WORDS`, `DEFAULT_COLOR`, `LATE_BORDER` (couleur de retard `LATE_COLOR`), `ALL_DAY_ROWS` = 2 ; semaine `timeGridWeek` de `weekLength(currentWeek())` jours, `firstDay` = `calendarFirstDay(week)`.

## components

### `components/EventForm.tsx`

- `EventForm({ context, occurrence?, defaults?, onDone, onDuplicated?, scope? })` : formulaire de création (« Créer l’évènement », en bas) ou panneau d’une occurrence enregistré champ par champ (`useFieldSave` : textes, liens, lieu et trajets en les quittant ; jours, heures et répétition ensemble (interne `TIMING`) au `onCommit` d’`EventRepetition` ; le reste dès qu’il change), disposé par `DetailLayout` ([Panneaux](../../components/panels.md#detaillayouttsx)), pour la portée choisie à l’ouverture (`scope`, défaut `ALL` ; `null` : question fermée sans choix, lecture seule — `readOnly`, texte « Lecture seule : aucune portée n’a été choisie à l’ouverture… », commentaires ouverts, pas de menu). Interne `SaveTarget` : où vont les enregistrements (`eventId`, `occurrenceDate`, `scope`, `ruleStart`), lu dans une référence par chaque enregistrement : après « celle-ci et les suivantes », la nouvelle série (id renvoyé par `update`) est modifiée en entier ; après « toutes », l’occurrence suit son nouveau jour, et une série décalée reprend la règle et le premier jour de la série de l’occurrence (`shiftedSeries`, `cutSeries` après une coupure, puis `seriesOn`, comme l’API : un décalage mixte en fait plusieurs ; le dernier jour du mois, la règle choisie que `update` renvoie, `movedRule`) ; « cette occurrence » reste l’exception de son jour. Valeurs de départ : `occurrenceInput` pour « cette occurrence », `seriesInput` sinon (une occurrence modifiée seule : les champs de sa série). Jours changés : ses liens de routines suivent (`withDays` : décalés depuis le jour où chaque occurrence s’affiche, `shownDate` envoyé, l’API lie l’occurrence affichée ce jour-là ou retire le lien), au report aussi. Avec « cette occurrence », les champs de la série (répétition : `EventRepetition` `ruleLocked`, calendrier, projet, assignés, bénéficiaires, catégories, tâches, documents, rappels) sont en lecture seule (`Fieldset` `display="contents"`, fonction interne `series`), avec « Cette occurrence seulement : … ». `useAppForm` + `calendarEventInputSchema`. En-tête : « Libellé », menu « … » (`ActionsMenu`, entrées de `useEventMenu` sur les champs du formulaire, la cible `SaveTarget`, la lecture seule, les minuteurs enregistrés du panneau, `onDuplicated` et `onDone`); projet (`ProjectSelect`) ; badges « Annulé », « Reporté », « Archivé » ; `SaveStatus` ; lignes (`notes`) du report (« Il reste dans l’agenda, barré. Reporté au … », « Report de l’évènement « X » du … »), de l’archivage, de la portée. Colonne principale : description (`FormDescription`), « Relations » (`collapsible`, développé à l’ouverture, résumé : le nombre de tâches et de routines ; tâches : `timeTaskOptions`/`timeTasks`, `sharePeople` ; routines : `useRoutineOccurrences`, `routineLinkKey`/`routineLinkOf` ; une occurrence gardée à part sur un jour de l’évènement aussi, rangée par le jour qui l’identifie, « (déplacée du …) »), « Commentaires » de l’occurrence (`Comments` avec `occurrenceDate`, sans titre propre). Colonne de droite (`PanelGroup`, `PANEL_GROUPS`, tous `collapsible`, réduits sauf « Classement », résumés internes `summaries` (« Ressources » : liens, documents et fiches, `useSheetLinks`, la requête de `SheetsSection`, chargée une fois), `invalid` par `hasFieldError`) : « Classement » (calendrier `itemSelectProps`, catégories `treeSelectProps` + `categoryOptions`, création `itemCreator`), « Parties prenantes » (« Assignés » : `BeneficiariesSelect` avec `label`, les contributeurs `assignableFor` du projet et les relations, écrits dans `contributorIds` et `relationIds` ; « Bénéficiaires » : `BeneficiariesSelect`), « Dates et heures » (`EventRepetition` dans le panneau, `AvailabilityHint`, `TrackedTime` : chrono `eventTimerInput`, celui qui tourne sur l’occurrence `onEventOccurrence`), « Lieu » (`EventLocation` par `useFormLocation`, `TravelTimes` pour un évènement à heures avec « Partir à … » depuis le début, `shiftTime`), « Alarmes » (`EventRemindersField` de [Composants de saisie](../../components/inputs.md#itemreminderstsx), aide selon la journée entière ; `SavedCountdownsField` `EVENT`, toute la série, gardés dans un état du panneau, `onSaved`), « Ressources » (`LinksField`, `DocumentsField` de [Code web : documents liés](../cross-cutting/documents.md), champ de la série ; `SheetsSection`). Projet changé (interne `changeProject`) : les documents de projet hors de la nouvelle arborescence sont retirés du formulaire (`resourcesInTree`), notification « N document(s) de projet retiré(s) : hors de l’arborescence du nouveau projet. ». Lecture seule si l’évènement ou son calendrier est archivé. Utilisé par `useEventForm`.
### `components/EventPostpone.tsx`

### `components/EventTimerToggle.tsx`

- `EventTimerToggle({ context, occurrence, disabled?, size? })` : « Démarrer le chrono » d’une occurrence d’un évènement dans une ligne, ou arrêt de celui qui tourne dessus (`TimerToggle`, `useRunningTimers`, `runningOn` + `onEventOccurrence`) : le chrono prend son projet et ses tâches liées, comme « Temps passé » de son panneau (`eventTimerInput`) ; désactivé pour un évènement archivé ou d’un calendrier archivé (`useCalendars`), sauf `disabled` donné. ### `components/EventRepetition.tsx`

`EventRepetition({ value, onChange, onCommit?, ruleStart, error?, ruleLocked? })` : jours, heures et répétition d’un évènement, directement dans son panneau (groupe « Dates et heures », pas de fenêtre ; chaque changement donné aussitôt par `onChange`, `onCommit` après un choix — fréquence, jours, fin, pause, période, journée entière… — et après un nombre quitté — intervalle, nombre de fois… : le panneau enregistre alors) : la règle (`RuleEditor` commun, voir [Répétition](../../components/recurrence.md) : fréquence, fin, pauses), « Journée entière », « Période » (`PeriodField` avec les heures, `keepLength` : déplacer le début garde la longueur ; d'autres jours remettent la durée de la règle à zéro ; l’erreur dessous), durée des occurrences (journée entière répétée, `DURATION_UNITS`, `spanEnd`). `ruleLocked` (une occurrence modifiée seule) : seulement journée entière, jours et heures, sans la règle. Type interne `EventTiming`. Utilisé par `EventForm`.

### `components/AvailabilityHint.tsx`

`AvailabilityHint({ allDay, startDate, startTime, endDate, endTime })` : avertissement (`NoticeAlert`) d’un évènement à heures, enregistré quand même : pendant un créneau « Indisponible » de l’espace (jours et heures du panneau à l’heure de Paris, `parisInstant`, `useSlotRules().unavailable`, `unavailableWarning` : « Pendant « Sommeil » (indisponible). », tout espace, sur plusieurs jours aussi), et, sur un jour, hors des heures de travail de l’espace (interne `workingHoursWarning` : `useWorkingHours`, PRO seulement ; éphémérides exclues ; créneaux archivés ou d’un type archivé exclus ; `plannedSlots`, `withinSlots`, `plannedPauses`). Rien en journée entière. Utilisé par `EventForm`, `PostponeForm`.
